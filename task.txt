=====================================================================
Финальный проект модуля — разработка асинхронного HTTP прокси сервера
=====================================================================

Вы изучили асинхронное программирование и сопрограммы в C++20. Чтобы применить 
эти знания на практике, предлагаем выполнить проектную работу, в процессе 
которой вам предстоит разработать быстрый и эффективный сервер, проксирующий 
запросы по протоколу HTTP, в том числе:

* класс, который принимает соединения и запускает прокси-сессию;
* сопрограмму, которая реализует прокси-сессию;
* алгоритм проксирования с использованием асинхронных функций чтения и записи;
* функции парсинга HTTP-заголовков.

Сервер работает на одном потоке, при этом обрабатывает множество одновременных 
запросов за счёт кооперативной многозадачности.

======================================
План реализации проекта AsyncHttpProxy
======================================

1. Подготовьтесь к работе:

* Откройте шаблон проекта AsyncHttpProxy.
* Выполните инструкции в разделе «Начало работы».
* Соберите проект и запустите приложение по шагам в разделе «Сборка проекта и 
запуск тестов».

2. Закончите реализацию недостающих компонентов класса Server:

* Реализуйте установку соединения от HTTP-клиента.
* Поддержите возможность устанавливать множество соединений в рамках одного 
класса Server.
* Поддержите запуск session на каждом установленном соединении.

3. Реализуйте функцию парсинга HTTP-заголовков. Выберите наиболее подходящий 
контейнер для работы с именем заголовка и его значением. Рекомендуем повторить 
урок про строки третьего модуля.

4. Закончите реализацию сопрограммы session:
* Реализуйте чтение заголовков со стороны клиента. Из заголовков получите адрес 
сайта, значение Host.
* Установите соединение с указанным сайтом.
* Реализуйте чтение заголовков со стороны сайта. Из заголовков получите размер 
тела в байтах, значение Content-Length.
* Реализуйте передачу тела от сервера клиенту.

5. Завершите работу:
* Протестируйте разработанные функции парсинга, разработав несколько тестов во 
фреймворке GTest.
* Протестируйте работу сервера с помощью утилиты wget.
* Проверьте обработку граничных случаев (пустое тело, отсутствие заголовков 
"Host" или "Content-Length").
* Убедитесь, что код соответствует современным стандартам C++.
* Убедитесь, что используются современные возможности C++23, включая co_await, std::views::split, std::println, std::format.
* Убедитесь, что используются примитивы Asio для работы с сетевым 
вводом-выводом: awaitable, use_awaitable, co_spawn, tcp::socket, async_read, 
async_read_until, async_write, transfer_at_least.

===============================
Требования к результатам работы
===============================

Общие требования к проекту

1. Должна быть реализована возможность посещать сайты по протоколу HTTP, 
используя программу в качестве прокси-сервера.
2. Должна быть реализована возможность поддерживать работу нескольких сессий 
одновременно.

======================
Технические требования
======================

1. Не должно создаваться дополнительных потоков, вся программа должна 
выполняться на одном основном потоке (tid == pid).
2. Сетевое взаимодействие должно быть реализовано с использованием boost::asio и 
сопрограмм C++20.

===================================
Чек-лист для проекта AsyncHttpProxy
===================================

Обязательные требования

Структуры данных и классы:

* Реализован класс Server.
* Реализована сопрограмма session.
* Реализованы функции парсинга заголовков.
* session запускается в методе on_accept с помощью co_spawn.
* Чтение заголовков производится с помощью метода async_read_until.
* Реализованы функции парсинга заголовков с помощью std::views::split и std::string_view.
* Для записи используется co_await и async_write с use_awaitable.
* Для чтения используется co_await и async_read с use_awaitable.
* При возникновении исключительных ситуаций обработка происходит в блоке try/catch.
* При завершении работы session-сокеты закрываются.

Функциональность:

* Реализована функция iterHeaders.
* Реализована функция findHost.
* Реализована функция findContentLength.
* Реализован метод on_accept.
* Реализована сопрограмма session.

Тестирование:

* Реализованы юнит-тесты на парсинг заголовков — рассмотрены случаи, когда 
заголовок найден и не найден.
* Сервер протестирован с помощью утилиты wget и python3.

Использование современного C++:

* Используются std::views::split, std::string_view, std::println.
* Используются сопрограммы C++20.
